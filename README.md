# 雨课堂助手（自动签到 + 自动答题）

雨课堂的自动化小工具，带图形界面：自动等课、自动签到进课堂、实时监听题目并自动作答，支持多账号同时挂机。

核心逻辑整理自 [timeflykai/lazytool](https://github.com/timeflykai/lazytool) 的雨课堂部分，在原基础上补上了图形界面、多账号管理、强制重新扫码、日志与历史记录，并修复了一处首次登录必崩的 bug。原项目里的学习通部分与雨课堂没有任何调用关系，因此没有包含在这个仓库里。

> 仅供个人学习与研究使用，请遵守所在学校的规定，使用风险自负。

---

## 功能

- **自动等课**：每 30 秒查询一次有没有课正在进行，检测到就自动签到进课堂；登录状态失效会立刻提示并自动弹出新二维码，不会一声不吭地白等。
- **自动答题**：通过 websocket 实时监听课程事件，题目下发后随机延迟 10–20 秒再作答，避免过于机械。答案优先用雨课堂下发的，拿不到时可以用大模型生成（详见「自动答题的答案从哪来」）。
- **图形界面**：二维码直接显示在窗口里，不用再开图片查看器；界面不联网，所有真实动作都交给后台子进程执行。
- **多账号**：每个账号各自一份登录状态、二维码、日志和历史，可以同时挂多个人的账号，互不干扰。
- **强制重新扫码**：一键拿一张全新二维码，扫完自动接上监听。
- **历史记录**：签到、下课、作答、异常等关键事件按时间落盘，界面里可以直接查看。
- **运行日志**：每轮任务单独写一份日志文件，出问题好排查。
- **可选的微信推送**：配置企业微信后，可以把状态和二维码推到手机（默认关闭）。

## 安装

在仓库根目录打开命令行（PowerShell 或 CMD），执行：

```bat
cd /d 本仓库路径
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

如果 `py` 命令不可用，把上面的 `py -3` 换成你本机 Python 的完整路径即可，例如：

```bat
"C:\Users\你的用户名\AppData\Local\Programs\Python\Python313\python.exe" -m venv .venv
```

装完依赖后，仓库根目录会出现 `.venv` 文件夹，之后所有命令都用 `.venv\Scripts\python.exe` 运行，不会污染你本机的 Python 环境。

## 快速开始

### 一、图形界面（推荐）

双击仓库根目录的 **`gui.bat`**，窗口打开后：

1. 左侧默认已有一个账号 `me`，选中它。
2. 点顶部 **「刷新登录二维码」**，窗口中间会出现一张微信二维码。
3. 用手机微信扫码，手机上确认登录。
4. 扫码成功后程序会**自动开始监听**，界面上会依次显示「扫码登录完成」「等待有课进行中」。
5. 之后只要有课正在进行，它会自动签到进课堂，并在有题目下发时自动作答。

### 二、命令行

```bat
cd /d 本仓库路径
run.bat                # 打开交互菜单
```

或者直接跑某一条命令：

```bat
.venv\Scripts\python.exe run.py login      # 扫码登录（首次必做）
.venv\Scripts\python.exe run.py            # 交互菜单
```

命令行模式下，扫码登录会把二维码存成 `qrcode_账号.jpg` 并自动用系统看图软件打开，扫完即可。

## 图形界面说明

窗口分成左右两块。

**左侧：账号列表**

每个账号后面直接标着当前状态（监听中 / 已登录 / 未登录 / 未校验），下面三个按钮分别是「添加账号」「移除账号」「环境自检」。

添加账号时会让你起一个标识名（用于区分各自的登录状态文件），并询问是否立刻开始监听。移除账号只会把它从列表里去掉，登录状态文件会保留，重新添加同名账号就能继续用，不必重新扫码。

**右侧上方：状态卡片**

- **登录**：显示 cookie 是否有效，有效时会带上账号真名（选中账号时会自动校验一次）。
- **监听**：未运行时显示「未运行」；监听中显示大约剩余的分钟数；扫码等待期间显示已等了多久。
- **课程**：当前有没有课在进行，有课时会显示 lessonId 与课程名。

**「登录与监听」标签页**

| 按钮 | 作用 |
| --- | --- |
| 开始监听 | 本地 cookie 有效时直接开始等课，不会再要求扫码 |
| 停止 | 结束当前账号的后台进程 |
| 刷新登录二维码 | 强制换一张新二维码，扫完自动开始监听；当前有任务时会先停止 |
| 校验登录状态 | 立刻查一次 cookie 是否有效、当前有没有课 |
| 放大二维码 | 把当前二维码用看图软件弹出放大，方便手机扫 |

左边的二维码区域会实时显示当前二维码，并给出「约 xx 秒后失效」的提示；过期后会直接显示「二维码已过期」，不会再让你扫一张已经失效的码。二维码大约 2 分钟失效一次，程序会自动换新，界面上的图也会跟着更新。

**「历史记录」标签页**

记录扫码登录成功、检测到课程、获取到幻灯片、提交作答、课程结束、运行异常等关键事件，带时间戳。历史保存在根目录的 `history_账号.log` 里，可以点「刷新」重新读取，或「清空本账号历史」。

## 命令行用法

| 命令 | 说明 |
| --- | --- |
| `run.py` | 打开交互菜单 |
| `run.py check` | 环境自检：依赖是否齐全 + 雨课堂能否连通 |
| `run.py login` | 强制扫码登录，换一张新二维码（扫码成功才覆盖旧登录状态） |
| `run.py status` | 查看登录状态、当前有没有课 |
| `run.py ykt` | 开始监听：等课 → 自动签到 → 监听题目并自动作答 |

以上命令都支持 `--name 账号标识` 来指定账号，例如：

```bat
.venv\Scripts\python.exe run.py ykt --name 张三
.venv\Scripts\python.exe run.py status --name 张三
```

不同 `name` 使用互相独立的 `cookie_名称`、`qrcode_名称.jpg` 等文件，因此可以同时跑多个账号。

## 配置说明

首次运行会在根目录生成 `config.json`（模板见 `config.example.json`）：

```json
{
  "yuketang": {
    "name": "me",
    "wx": false,
    "debug": true,
    "open_qrcode": true,
    "lesson_filter": "",
    "checkin_source": 1,
    "answer": {
      "source": "auto",
      "api_key": "",
      "api_key_env": "",
      "base_url": "",
      "model": "",
      "timeout": 30
    }
  }
}
```

| 字段 | 说明 |
| --- | --- |
| `name` | 默认账号标识，命令行不传 `--name` 时用它 |
| `wx` | 是否把消息推到企业微信，默认 `false` |
| `debug` | 是否输出 `发送给xx的消息: ...` 这类调试信息，默认 `true` |
| `open_qrcode` | 扫码后是否自动用看图软件打开二维码。命令行建议 `true`，图形界面会自动把它设为 `false`（因为二维码已经显示在窗口里） |
| `lesson_filter` | 同一时间有多节课在进行时，只签到课程名包含这个关键词的课；留空就按服务端返回的第一节处理 |
| `checkin_source` | 签到请求里的 `source`，雨课堂用它记录这条考勤的「签到方式」，默认 `1`（微信/扫二维码）；改成 `5` 就会记录成「通过公众号/"正在上课"提示进入课堂」 |
| `answer.source` | 答题答案来源：`server` 只用雨课堂下发的答案 / `ai` 只用大模型 / `auto` 先看雨课堂、拿不到再用大模型 |
| `answer.api_key` | 大模型 API Key；留空时按下面顺序找：`api_key_env` 指定的环境变量 → `DEEPSEEK_API_KEY` / `DEEPSEEK-API-KEY` / `DASHSCOPE_API_KEY` 等常见环境变量 → 根目录 `dashscope_key.txt` |
| `answer.api_key_env` | 想指定用哪个环境变量时填这里（例如 `DEEPSEEK-API-KEY`），留空就按上面的顺序自动找 |
| `answer.base_url` | 大模型接口地址；留空时按 Key 的来源自动选（DeepSeek 用 `https://api.deepseek.com/v1`，百炼用 `https://dashscope.aliyuncs.com/compatible-mode/v1`） |
| `answer.model` | 大模型名称；留空时按 Key 的来源自动选（`deepseek-chat` / `qwen3.8-max`） |
| `answer.timeout` | 单次调用大模型的超时秒数，默认 30 |

### 签到方式是怎么决定的

雨课堂的「签到方式」不是客户端能随便写的文案，而是**进课堂请求里的 `source` 值**对应的：官方前端会把这个值从页面 URL 的 `?source=` 读出来，再放进签到请求体的 `source` 字段里（`this.source = query.source || 5`，请求体是 `{source, lessonId}`）。

雨课堂没有公开过这个枚举，下面的对照来自公开客户端和社区实现的整理，仅供参考：

| `checkin_source` | 记录出来的签到方式 |
| --- | --- |
| `1` | 微信 / 扫二维码（默认） |
| `5` | 通过公众号/"正在上课"提示进入课堂 |
| `14` | PC / Web |
| `21` | 二维码 |
| `22` | 暗号 |
| `23` | APP 点击课堂 |
| `91` | 旁听（观摩） |

想换成别的入口，改 `config.json` 里的 `checkin_source` 就行，程序启动时日志里会打印当前用的是哪个值。如果记录出来的方式和预期不符，说明雨课堂调整过这个枚举：这时候拿手机扫一次老师屏幕上的课堂二维码，在微信里把链接复制出来（右上角 `···` → 复制链接），链接里 `source=` 后面的数字就是抄二维码入口要用的值，填进去即可。

### 自动答题的答案从哪来

雨课堂已经不再向学生端下发课内题的正确答案了：幻灯片接口里的 `answers` 字段一直是空的，所以老版本“直接把服务端答案提交上去”的做法，实际上提交的是空答案（日志会显示成 `答案=[]`），而程序还误以为作答成功。

现在程序改成：

1. 先找雨课堂下发的答案，真的有内容才提交；
2. 没有答案时，按 `answer.source` 决定是否交给大模型生成答案；
3. 两条路都拿不到答案，就直接记成「跳过作答」，并把题目原始数据写到 `debug_problem_课程_题目.json`，不会再拿空答案去交白卷。

想启用 AI 作答，只要让程序能找到大模型 API Key 就行，三种写法任选：填 `config.json` 的 `answer.api_key`、把 Key 放进同名环境变量、或写进根目录的 `dashscope_key.txt`。Key 在环境变量里时（例如机器上已经有 `DEEPSEEK-API-KEY`），接口地址和模型会自动按来源选好，不用手填。所有服务走 OpenAI 兼容的 `/chat/completions` 接口，想换成别家把 `answer.base_url` 和 `answer.model` 填上即可。找不到 Key 时程序只使用雨课堂下发的答案，功能一切照旧。

### 企业微信推送（可选，默认关闭）

想让签到和答题记录推到手机微信，需要自己建一个企业微信应用，然后填写 `qywxbot/send.py` 顶部的三个常量：

```python
AgentId = '你的 AgentId'
Secret = '你的 Secret'
CompanyId = '你的企业ID'
```

再把 `config.json` 里的 `wx` 改成 `true`。三个常量留空或仍是 `xxx` 时，程序会自动降级为只输出到控制台，不会报错。

## 常见问题

**二维码扫不了 / 提示过期？**

一张二维码大约 2 分钟失效。图形界面里点「刷新登录二维码」换一张即可，程序自身也会每 2 分钟自动换新。界面上如果写着「二维码已过期」，说明那张确实已经不能扫了。

**登录状态能保存多久？**

登录状态保存在本地 `cookie_账号` 文件里，文件本身不会自动过期或删除，只有重新扫码才会被覆盖。真正会过期的是服务端会话，可维持数周量级（原作者说明约两周，实测少则数小时多则跨天均保持有效）。失效时界面会提示「未登录或已失效」，点「刷新登录二维码」重扫即可。修改密码、在别处重新登录可能让它提前失效。

**为什么挂着挂着就退出了？**

上游代码里有 `time.time() - start_time < 6000` 的限制，也就是**单次运行最多 100 分钟**，签到监听和答题监听共用这个计时。因此建议在上课前再启动，而不是提前挂太久。

**界面报「没找到 .venv」？**

说明还没装依赖，按上面的「安装」一节创建虚拟环境即可。

**双击 gui.bat 没反应？**

先手动跑一次 `.venv\Scripts\python.exe gui.py`，这样能看到报错信息；界面启动失败时也会在根目录留下 `gui_error.log`。

**为什么窗口里没有二维码只有文字？**

没安装 pillow 时会退化成文字提示，此时只能点「放大二维码」用看图软件查看。执行 `.venv\Scripts\python.exe -m pip install pillow` 即可恢复窗口内显示。

**能同时帮别人挂账号吗？**

可以。每个账号在界面上单独添加，各自扫码一次，然后各自点「开始监听」。多个账号的监听进程相互独立，只是同一时间只有一个界面，注意别把窗口关掉（关窗口会确认后一并停止所有监听）。

## 工作原理

1. **登录**：向 `wss://www.yuketang.cn/wsapp/` 请求一张微信登录二维码，扫码后把拿到的 cookie 存到本地文件，之后启动就复用这份 cookie，不再需要扫码。
2. **签到**：轮询 `classroom/on-lesson-upcoming-exam` 判断有没有课正在进行，有课就调用 `lesson/checkin` 获取本次课堂的 lessonToken。
3. **监听与答题**：用 lessonToken 建立 websocket 连接，服务端在开始播放幻灯片、下发题目等时机会推送事件；收到题目事件后随机延迟 10–20 秒再作答，答案来自雨课堂下发的数据，拿不到时按配置交给大模型生成。
4. **保活**：等课期间每 10 分钟、跟课期间每 5 分钟输出一条心跳，界面上能看到「最近事件几分钟前」，超过 20 分钟没有任何输出就会提示可能卡住；cookie 失效则立刻退出并自动刷新二维码。

## 已知限制

- 雨课堂已经不再向学生端下发课内题答案，不配置 `answer.api_key` 时只能跳过作答，不会提交空答案。
- 上游代码在多线程与异常处理上比较简陋，遇到网络波动会自动重试，但长时间挂机仍建议单独开一个窗口观察。
- 依赖服务端接口与 websocket 协议，对方一旦调整就可能失效。
- 图形界面只在 Windows 桌面环境验证过。

## 与原仓库的差异

- 修复 `yuketang/yuketang.py` 中 `__init__` 里 `start_time` 的初始化顺序问题：原代码先调用 `getcookie()` 后赋值 `start_time`，导致首次运行走扫码登录分支时必然抛 `AttributeError`，也就是说原仓库在不预置 cookie 的情况下无法完成首次登录。
- 新增图形界面 `gui.py` / `gui.bat`，支持多账号、二维码窗口内显示、手动刷新二维码、日志与历史记录。
- 新增命令行入口 `run.py` / `run.bat`、配置模板、依赖清单与 `.gitignore`。
- 修复图形界面的中文乱码：子进程原来按系统 GBK 输出、界面按 UTF-8 解码，导致日志和「历史记录」里的关键字全部匹配不上；现在统一按 UTF-8 输出。
- 答题不再提交空答案：雨课堂不再下发课内题答案，拿不到答案时记「跳过作答」并保存题目原始数据，同时新增可选的 AI 作答（`answer.source`）。
- 给所有雨课堂请求补上超时，websocket 重连加了退避，cookie 失效会立刻提示并自动刷新二维码；同时进行多节课时会把候选都写进日志，并支持用 `lesson_filter` 指定课程。
- 未改动的部分：`yuketang/util.py`、`qywxbot/send.py`，以及 `yuketang/yuketang.py` 的其余逻辑。
